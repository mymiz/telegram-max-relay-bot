# Telegram → MAX: передача кода входа

Бот-посредник между владельцами номеров MAX и администратором. Владелец регистрирует номер, администратор запрашивает SMS-код или пароль, владелец отправляет — бот пересылает.

---

## Структура проекта

```
bot.py          ← вся логика бота (команды, кнопки, FSM, обработчики)
storage.py      ← SQLite-хранилище (владельцы, очередь, балансы, лог)
.env            ← токен и ID администратора (не коммитится)
deploy/         ← Docker, Railway, инструкции деплоя
data/           ← база данных store.db (создаётся автоматически)
```

## Переменные окружения (.env)

| Переменная | Обязательна | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | ✅ | Токен от @BotFather |
| `ADMIN_USER_IDS` | ✅ | ID администраторов через запятую |
| `REDIS_URL` | ✅ | URL Redis (для FSM-состояний) |
| `OWNER_USER_IDS` | — | Белый список владельцев (пусто = любой) |
| `CODE_REWARD_RUB` | — | Вознаграждение за код (по умолчанию 50) |
| `RATE_LIMIT_SEC` | — | Антиспам для сообщений (по умолчанию 1.0 сек) |
| `CALLBACK_RATE_SEC` | — | Антиспам для кнопок (по умолчанию 0.3 сек) |
| `TELEGRAM_PROXY` | — | HTTP-прокси для бота |
| `ALLOW_LOCAL` | — | Разрешить локальный запуск (=1) |

## Роли и возможности

### Владелец
- Регистрирует номера MAX через кнопку «📱 Сдать номер»
- Видит свою позицию в очереди сразу при добавлении
- Получает уведомление когда его номер взяли в работу
- Отправляет SMS-код или пароль (любые символы) по запросу
- Просматривает баланс, статистику и историю номеров
- Запрашивает вывод средств (мин. 1$, макс. — текущий баланс)

### Администратор
- Видит очередь и берёт номера в обработку
- Запрашивает SMS-код или пароль у владельца
- Подтверждает «Встал» / пропускает / банит номер
- Управляет балансами: `/addbal ID сумма`
- Просматривает профили: `/profile ID`
- Одобряет или отклоняет запросы на вывод (кнопками в чате)
- В Настройках: меняет прайс, статус бота, делает рассылку
- **Экспорт CSV** — список всех владельцев с балансами
- **Лог действий** — последние 50 событий (добавления, коды, выводы, рестарты)

---

## Логика работы

1. Владелец добавляет номер → попадает в очередь
2. Администратор берёт номер → владелец получает уведомление «взяли в работу»
3. Администратор нажимает «Код» или «Пароль» → владельцу приходит запрос (60 сек)
4. Владелец отправляет код/пароль → администратор получает его мгновенно
5. Администратор нажимает «Встал» → владельцу начисляется вознаграждение через 5 мин
6. Если прайс не указан → бот автоматически переходит в статус «выключен»

---

## Безопасность и надёжность

- Один активный запрос на всех — очередь обрабатывается последовательно
- Два администратора не могут одновременно захватить один слот (атомарная резервация)
- Каждый администратор управляет только своим активным запросом
- FSM-состояния изолированы по пользователю (Redis)
- Режим кода/пароля сбрасывается при каждом новом запросе
- `.env` не попадает в Git
